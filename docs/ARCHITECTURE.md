# 架构与数据流

## 模块

| 文件 | 职责 |
|---|---|
| `dashboard.py` | 本机 HTTP 服务、接口、CSRF/Origin 校验、模型连通性测试 |
| `app_store.py` | SQLite 设置、模型配置、草稿、消息缓存、事件和用量 |
| `app_engine.py` | 单联系人监听、草稿队列、上下文过期判定、发送与核验 |
| `app_models.py` | Codex CLI、自定义 API、配置独立凭据、回复结构校验 |
| `app_usage.py` | JSONL/SSE 事件读取、服务端 usage 标准化、实时进度 |
| `reader.py` / `wechat_backend.py` | 只读解密 VFS、WAL 快照、联系人及最近消息读取 |
| `media_context.py` | 图片解码、表情内容、生成上下文组装 |
| `native_access.py` / `native_send.py` | 微信无障碍控件、界面发送和数据库回读核验 |
| `runtime_paths.py` | 私有机器配置和依赖路径 |
| `web/` | 无打包依赖的本机网页前端 |

HTTP 请求由服务器线程处理；微信读写由一个后台引擎线程串行调度；模型生成使用单独线程池。生成期间仍检查新消息。连通性测试使用独立线程池，不接触微信发送。

## 草稿状态

`queued → preparing → generating → awaiting → send_queued → sending → sent`

- `stale`：生成期间或确认前有新消息，需要重新生成。
- `superseded`：已创建修改版本，父草稿保留。
- `cancelled` / `skipped`：不会发送。
- `partial`：只完成部分内容，例如表情在点击前被拦截。
- `uncertain`：点击后结果无法确认，暂停自动处理，不盲目重发。

审批使用版本号和状态的原子检查。发送前重新读取对话，逐条发送后回读数据库。新消息或本人手动回复出现时，剩余旧内容不再发送。

## 多模型配置

SQLite `model_profiles` 保存配置 ID、显示名、模型来源、Base URL、模型 ID、协议、推理强度、流式开关和版本号。`settings.active_profile_id` 决定下一轮使用的配置。

密钥不在 SQLite 中。每个新配置使用独立的 Windows 凭据项；旧单模型配置迁移为 `custom-migrated`，引用原来的 `legacy` 凭据，不复制密钥明文。内置 `codex-default` 不能删除。删除当前配置前必须先切换。

每轮开始时抓取设置快照和对应密钥，配置切换不会把正在生成的一轮换到另一个账户。草稿的 `configuration` 保存不含密钥的配置快照。修改未启用的配置不会自动切换模型。

## 当前上下文规则

最近 100 条双方消息；保留发送者和时间，移除系统消息。图片选择本轮新图及最近消息前 30 分钟内的最后 3 张图，附件总数不超过 5。表情使用已知描述或图片。风格开关开启时，额外带入 STYLE.md 和已有样本中的最后 35 组。不是按 token 预算裁剪，也没有滚动摘要或长期记忆检索。

自定义 API 每轮完整传入整理后的上下文；未使用 Responses 的 previous_response_id，也未启用模型工具。Codex 使用独立 ephemeral CLI 调用。

## 用量

`model_calls.call_id` 是计数单位。缓存 token 是输入子集，推理 token 是输出子集，不能重复加到合计。缺失字段用 null，旧记录不伪造为零。生成完成、失败、取消都保留已上报用量；发送事件只关联相同调用，不新计一次消耗。

## 微信适配边界

固定使用仓库中注明来源和校验值的适配器快照。读取路径不写原数据库。无障碍适配会修改运行中微信的一个已校验开关，安装文件不变。控件点击仍可能短暂激活窗口；版本变化、窗口状态和媒体缓存缺失都可能导致失败。


## 多联系人隔离

`app_contacts.Contacts` 在主库 `contacts` 表保存稳定账号，原联系人使用 `legacy` 并保留原库历史。新增联系人以生成的 UUID 为文件名，记录写入私有 `app-data/contacts/<id>.sqlite3`。`ContactStore` 只共享模型和设置，原始聊天、草稿、事件、用量不跨库。新增联系人禁用旧联系人风格示例。

每人一个 Engine、消息水位和生成队列。数据库解密 VFS 共享只读密钥映射，SQL 查询各开独立连接。微信发送用进程级 SEND_LOCK 包住选人、点击、发送核验；发送前重新查询稳定账号，要求唯一显示名且备注未变，避免按重名发送。备注变化需要重新连接和重新生成。HTTP 请求使用 peer_id 定位引擎；不存在于该库的 job_id 无法跨联系人审批。浏览器选择存在 sessionStorage，不改变其他标签页选择。

重启不重放旧生成和发送，新增联系人不会自动开启。全部暂停依次获得各引擎发送门锁，已开始的点击不能撤回。
