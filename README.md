# 微信回复台

打开 **http://127.0.0.1:8765**。这是本机管理页面，不对公网开放。

## 首次部署

1. 安装 Python 3.12+，在项目目录运行 `setup.ps1`。
2. 编辑本机 `local-runtime.json`：填写 `xwechat_files` 目录和目标联系人备注；如已有 `peer.json` 稳定账号标识则优先使用它。
3. 保持微信登录。内置模型还需要安装并登录 Codex CLI；也可使用自定义 API。
4. 根据需要提供私有的 `STYLE.md`、`reply_examples.json` 和 `stickers.json`。仓库只包含通用示例，不含真实聊天和表情。

## 启动与暂停

```powershell
.\start.ps1
.\stop.ps1
```

启动会打开页面并开始监听新消息；首次默认采用“先确认，再发送”。暂停会停止自动处理并取消生成中、排队中的任务，页面继续保留。已开始执行的发送动作不能撤回。暂停时仍可以主动生成草稿，并通过“确认发送”明确发送。

如需只打开界面、不立即监听，可以直接运行 `python dashboard.py`。关闭浏览器标签页不会关闭后台服务。电脑和微信需要保持运行与登录。

## 对话与草稿

- 页面显示最近对话、文字和表情。图片可点“查看图片”加载，“最新 ↓”回到最新消息。
- 新消息在开启监听后自动生成草稿。人工确认模式不会直接发送。
- 编辑草稿中的文字、选择或移除表情，点击“保存编辑”或直接“确认发送”。
- “不满意？告诉模型怎么改”可以填写修改要求，生成新版本；旧版本仍可查看。修改版本始终回到人工确认。
- “主动聊一句”不需要等待她发消息。填写话题或要求即可生成。开启自动模式且正在监听时，该按钮会明确显示“生成并自动发送”；其他情况下生成待确认草稿。
- 对话有新消息、本人手动回复、或发送前上下文发生变化时，旧草稿会标为过时，不直接发送。使用修改入口重新生成。
- 已发送的内容通过本地微信数据库核验；重复点击确认不会重复发送。无法确认发送结果时暂停自动处理，不盲目重试。

## 模型与 System Prompt

**内置 Codex**：使用本机 Codex CLI 的现有登录，默认 `gpt-6-astra / medium`。页面可修改 CLI 模型名和推理强度。实际可用性取决于现有账户。

**自定义 API**：填写 Base URL（例如 `https://api.example.com/v1`）、API Key、模型名，并选择 Chat Completions 或 Responses。支持的是相应 OpenAI 兼容请求格式，不保证每个代理服务都支持图片或同样的模型参数。

可以保存多个可编辑的模型配置：每项独立保存名称、Base URL、模型名、协议、推理/流式选项和 API Key。使用“新增配置”和“保存此模型配置”管理条目；点击“设为当前使用”切换。编辑未启用的配置不会自动切换。内置配置和当前启用项不能直接删除。

API Key 保存在 Windows 凭据管理器中，每个配置使用独立条目。原单模型配置会自动迁移，并继续引用旧凭据。配置数据库和普通日志不保存 Key；留空会保留已有 Key，勾选删除可清除。连通性测试使用当前表单中的值，不必先保存，也不会向微信发消息。

测试可使用自定义 testcase，显示实际返回内容、模型和耗时。可勾选绿色测试图片检查图片输入；文本连通成功不等于图片也可用。

System Prompt 中可以配置语气、详略和偏好。“参考我的历史表达风格”可独立开关。配置从下一轮生成生效，已经生成的草稿保留原模型和配置版本。提示词不能改变程序固定的收件人或绕过发送核验。

## Token 用量

页面顶部会显示当前模型操作的阶段、耗时，以及服务端已经上报的输入、输出、输入缓存命中、缓存命中率和总 Token。草稿卡片、连通性测试和运行记录也会保存这些指标。

- 只显示服务端或 Codex CLI 实际返回的数字，不用字符数推算计费 Token。
- Codex CLI 通常在 `turn.completed` 才返回用量；Chat Completions 的 `include_usage` 通常在流末尾返回。此前显示“用量尚未上报”，不是 0。兼容接口如返回中间用量，页面会持续更新。
- 缓存 Token 是输入的子集；推理 Token 是输出的子集，不重复加到总数里。命中率 = 缓存输入 / 总输入。
- 每次 Codex 执行或 API 请求有独立编号。文字和表情的发送记录引用生成用量，不将同一次模型调用重复计入。
- 失败、中断、取消的调用保留已收到的用量；缺失字段显示“—”。早期未采集的历史记录无法可靠补齐。
- 暂停会阻止未发出的回复，但已提交的模型请求可能继续完成并产生 Token，这部分用量同样保留。
- 自定义 API 默认使用流式请求。服务不支持 `stream` / `stream_options.include_usage` 时，可以在设置中关闭流式接收；完成后仍读取普通 JSON 响应里的 usage。

## 数据与故障

- `app-data/dashboard.sqlite3`：本机设置、草稿版本、最近消息缓存、运行记录。
- 页面“运行记录”：生成说明、发送成功、跳过表情和错误。旧版发送记录已导入。
- `dashboard.stdout.log` / `dashboard.stderr.log`：服务自身日志。
- 旧版 worker 脚本可能仍留在原部署电脑上作为回溯资料，不属于新仓库的运行入口；不要与新页面并行开启。
- 读取聊天使用本地数据库；发送仍复用已验证的原生控件方案，可能短暂激活微信窗口。若微信更新导致接口或控件变化，页面会显示具体错误，需要重新适配。

## 验证

```powershell
python -m unittest test_dashboard test_profiles test_usage
node test_browser.cjs
```

后端测试覆盖两种 API 协议、密钥错误、模型请求、审核过期、重复确认、暂停、发送不确定、修改版本和本机 HTTP 请求校验。浏览器测试会调用当前 Codex 生成验收草稿，但不点击确认发送。
